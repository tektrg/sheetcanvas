ClickHouse connector

Query ClickHouse into a refreshable SheetCanvas table.

Use the SheetCanvas ClickHouse connector when database results need to sit beside pivots, charts, sparklines, and notes. The browser calls the SheetCanvas backend proxy; it does not connect to ClickHouse directly.

Workflow fit

Best for read-only operational analysis.

The connector turns a saved ClickHouse query into a SheetCanvas table object. It is useful when a database result needs explanation, visual checks, or lightweight reporting context instead of another exported CSV.

Good fit

Repeated database checks

Save a connector and rerun the same read-only query when the source data changes.

Good fit

Canvas-based review

Place query results next to notes, pivots, and charts so assumptions stay beside the numbers.

Not the goal

Database administration

SheetCanvas blocks write-style SQL and is not a replacement for a ClickHouse admin console.

Setup

Run the connector through the backend proxy.

The frontend uses the backend connector API so ClickHouse credentials are stored server-side. For local development, start both the Vite app and the backend worker before opening the connector dialog.

  • Backend URL: set VITE_BACKEND_URL when the worker is not running at the default local backend address.
  • Optional API auth: if the backend uses API_BEARER_TOKEN, set the matching frontend VITE_API_BEARER_TOKEN.
  • Save connector: enter the ClickHouse HTTP URL, readonly username, password, and a connector name in the SheetCanvas data connector flow.
  • Create the sheet: run a SELECT or WITH query and place the returned rows on the canvas.

Guardrails

Queries are intentionally constrained.

The connector is designed for analysis reads. The backend validates query shape, adds limits where needed, and returns normalized errors to the app.

Read-only SQL

Queries must start with SELECT or WITH. Obvious write operations are rejected.

Single statement

Multi-statement SQL is blocked. Keep one focused query per connected sheet.

Row limits

The backend caps returned rows and marks truncated results so large queries do not overwhelm the canvas.

Refresh

Connected sheets remember the connector and SQL.

After a successful query, SheetCanvas stores connector metadata on the sheet so it can refresh the table later. The sheet updates its cells, dimensions, last refresh time, and truncation state from the latest backend response.

  • Source stays traceable: the table keeps the connector type, connector ID, SQL, and refresh timestamp.
  • Results stay visual: the refreshed table remains a canvas object that can sit beside charts, pivots, sparklines, and notes.
  • Errors stay visible: failed refreshes keep the prior sheet and store the latest connector error for the UI to surface.

Troubleshooting

Most failures point to backend config or query shape.

Start with the proxy and credentials before changing the canvas. The connector depends on the backend worker, encryption key, optional bearer token, and the ClickHouse HTTP endpoint.

  • Connectors do not load: check backend availability, VITE_BACKEND_URL, and any frontend bearer token.
  • Save fails: verify the backend has ENCRYPTION_KEY_B64 configured so it can encrypt stored passwords.
  • Query rejected: use one read-only statement beginning with SELECT or WITH.
  • Unexpected truncation: narrow the query or adjust the backend row limit for the deployment.
